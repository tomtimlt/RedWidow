# Plan — RedWidow V1 (1.0.0) : finir, prouver, publier

## Contexte

L'utilisateur veut une V1 publiable de RedWidow : GitHub public avec release et VS Code Marketplace, annonces, et un projet présentable dans une candidature chez Orange Cyberdefense. La V1 doit être **prouvée** et non seulement déclarée : recette manuelle tracée, démo sur une machine HackTheBox retirée, revue de sécurité.

État actuel (faits explorés) :
- Version 0.3.76 (`packages/vscode/extension.manifest.json:5`), `name: warband`, `displayName: RedWidow`, `publisher: warband` (provisoire), sans `repository`/`homepage`. Licence MIT au nom de « Warband contributors » (`LICENSE:1`).
- README : installation par VSIX, « not on the Marketplace yet » (`README.md:126-134`), avertissement d'usage autorisé (`README.md:20-22`), captures de l'ancienne identité (`README.md:24`).
- CI : `pnpm check` + build sur Linux (Node 22/24) et Windows (`.github/workflows/ci.yml`). Pas d'e2e VS Code ; tests de contrat désactivés par défaut.
- Release : `release.yml` publie directement sur tag (`gh release create` sans `--draft`, l.73-76), alors que `docs/livraison-0.3.76.md:41-43` parle d'un brouillon. `provenance.json` cité mais absent.
- Restes déclarés : `docs/architecture-issues.md:15` (contrat SDK réel « reste à faire »), `:28` (binaire SDK dans l'extension non testé), `:243-249` (lots B1–B7 « à faire »), `:261-` (« plus tard », dont une recommandation Apache-2.0 contradictoire avec MIT). Continuation automatique absente côté agent-sdk (`docs/livraison-0.3.76.md:31-32`).
- Contenus tiers : OWASP (CC-BY-SA-4.0), HackTricks (CC-BY-NC-4.0) via `cours/sources.json` ; non cités dans le README.
- Premier run réel de bug bounty : 8 correctifs identifiés (section A).

Rôles : l'implémenteur GPT code les sections A, B et F. Claude (orchestrateur) fait la revue de chaque lot et la revue de sécurité C. L'utilisateur fait la recette D, la démo E et les gestes de compte (éditeur Marketplace, jeton).

## A — Fonctionnalités finales (les 8 correctifs du premier run réel), puis gel

Un commit par lot, `pnpm check` vert, revue avant push. Contrats du dépôt : nouveau code `Reason` → `REASON_CODES` + fr/en ; nouveau `kind` → validateur + `KIND_CLASS` + `cli/format.ts`.

1. **Monitor complet** : retirer le filtre exec/Kali (`packages/vscode/src/logic/chat.ts:438-450`, `packages/vscode/media/ui.js:12-13,82-110`). Rendu `http_request` (méthode, URL, statut, octets ; rouge si erreur, délai ou arrêt de rythme), `read_url`, recherche web, `read_output`. Filtre « Tout / Shell / Web ». Tests vscode.
2. **Export du fil** : fonction pure `packages/vscode/src/logic/chat-export.ts` (Markdown + JSONL depuis `user.message`, `agent.text`, `tool.requested/result` limités à 4 Kio, `approval.decided`, `continuation.auto`, arrêts de rythme ; pensées exclues par défaut). Commande `warband.exportChat` + bouton, `chat.md` dans le ZIP d'audit (`audit-export.ts`). Ajouter `turn.*` et `continuation.auto` à `retained` (`packages/core/src/audit.ts:33-53`).
3. **`trace` lit l'export d'audit** (fichier `events-*.jsonl` ou ZIP) : désenvelopper `kind:"engine"`, tolérer `seq` absent (un seul avertissement). Fixture synthétique.
4. **Rythme par IP** : clé du contrôleur = IP résolue (réutiliser la résolution de `packages/core/src/web/network.ts:180`), groupe d'hôtes, reprise par groupe, ancien fichier d'arrêt relu. Délai dépassé après des réponses saines = bannissement suspect → pause du groupe 5 min, second signal → arrêt. Message au modèle listant les hôtes du groupe. La gate n'est pas touchée.
5. **Gros corps HTTP** : au-delà de 64 Kio ou pour du minifié, corps complet dans `outputs/warband-http-<id>/body.txt` (+ `body.split.txt` découpé) via `packages/core/src/docker/output-capture.ts` ; extrait tête + queue et ligne « à relire avec read_output ». Passer `outputs` au serveur web (`packages/vscode/src/engine/main.ts`).
6. **Relances en cours de tour** : `pendingNudge()` dans `mission-desk.ts`, note en pied de résultat des serveurs MCP du moteur (≤ 300 caractères, une toutes les 8 réponses au plus, sans répétition) ; recherche relancée dès la première technologie détectée.
7. **Créativité** :
   - méthode dans `methodology.ts` et les profils `bug-bounty`/`htb` (`agent-profiles.ts`) : hypothèse tirée d'une observation citée avant chaque sonde ; lire le JS et la logique métier avant d'attaquer ; sondes différentielles discrètes face à un WAF ; trois hypothèses non évidentes à chaque stagnation ;
   - mesure dans `trace` : ratio dérivé/générique et familles de technique.
8. **Alerte sans conteneur** : mission offensive avec `containers: []` → événement, ligne dans `mission_context`, bandeau Monitor.

**Gel** après A : plus aucune fonctionnalité jusqu'à 1.0.0, seulement des corrections issues de B à E.

- Revue de sécurité du diff entre la dernière version revue et `HEAD`.

- **Passage en public** : balayage de tout l'historique git à la recherche de secrets (gitleaks) et de données réelles. Aucune trace, URL ou réponse de cible réelle (programme réel quel qu'il soit) ni e-mail personnel ne doit se trouver dans le dépôt, l'historique ou les fixtures. Si un fichier sensible apparaît dans l'historique, le signaler à l'utilisateur avant toute réécriture ; ne rien réécrire sans son accord.

## D — Recette manuelle tracée (utilisateur)

`docs/v1/recette.md` : tableau de scénarios, chacun avec étapes, résultat attendu, et cases OS (Windows, Linux) / date / version / OK-KO / lien de preuve.

1. Installation du VSIX sur une machine propre, premier lancement, page d'accueil.
2. Branchement Exegol : conteneur attaché, `exec` visible dans le Monitor.
3. OpenCode + DeepSeek : configuration, premier run.
4. Claude Agent SDK : configuration, premier run (binaire empaqueté).
5. Projet, fiche programme, approbation par empreinte, hors-périmètre refusé.
6. Rythme : arrêt d'un groupe d'IP, puis `program resume`.
7. Bypass : activation, expiration, extinction à l'arrêt du moteur.
8. Engagement red team : fiche, plan de campagne, arrêt d'urgence et relâche.
9. Supervision `relentless` : continuation automatique visible.
10. Monitor complet, export du fil, ZIP d'audit, `trace` sur le ZIP.
11. Rapport de mission, Kill chain, Attack Flow exportés.
12. Désinstallation propre.

Tout KO devient un correctif, puis le scénario est rejoué. Le tag 1.0.0 attend que tout soit OK sur Windows ; Linux, au minimum les scénarios 1 à 5 et 10.
